# 无纸化检验台账 v2 — 需求

修订日期：2026-11-05。本文定义业务目标与验收，不代表现有代码或部署状态。配套文档：[功能说明](features.md)、[系统设计](design.md)、[公共设计](common-design.md)、[字段目录](fields.md)、[接口](api.md)、[参考资料](reference-data.md)。仅这套文档构成 v2 的设计依据，归档资料不产生隐含约束。

## 1. 定位与范围

将《镜片表面质量检验记录表》线上化，支持填写、补录、修改留痕、查找和统计。系统是检验台账，不管控实际生产路线。本工作区交付后端和对接契约；前端场景用于说明接口应支持的操作。Excel/CSV 导出、打印/PDF、历史台账导入纳入低优先级计划，核心闭环不依赖这些文件能力。

核心原则：各工序独立分批和填报；同一生产批的部分检验批次可先进入下一工序，不等待本工序全部完成。后序可以先录，前序以后补录。系统不要求提供跨工序来源对应，不计算批次间分配、可用余额、冻结、交接闭合或实物追溯链。

保存即生效，每次修改保留历史；没有发布、审批和修订草稿步骤。允许资料不完整和分次填写，不以数据缺失阻止正常保存。合法格式、权限、业务身份防重和并发控制仍须满足。

## 2. 术语与身份

| 术语 | 定义 | 不能混淆的概念 |
|---|---|---|
| 生产批（产品批） | 共享表单号与完整样品型号对应的共同业务范围 | 不是某一道工序的检验批次 |
| 共享表单号 | 同生产批跨工序共用的纸面业务号 | 不是单张检验单的全局唯一号 |
| 完整样品型号 | 识别生产批的完整文字 | 不是解析得到的 VID2 等型号片段 |
| 工序填报组 | 某生产批、某工序、某检验类型的记录集合 | 不表达前后置依赖或审批节点 |
| 检验批次 | 某工序自行划分的最小检验单位 | 跨工序同名批号不表示同一批实物 |
| 检验单 | 一张表单对应一个检验批次，具有稳定系统 ID | 不是跨工序共用的一张可覆盖表单 |
| 内容版本 | 一次保存后的完整内容及操作者、时间 | 不是一次新的检验，也不新增检验量 |
| 明细行 | 单据内的计数/缺陷行 | 不是新的实物批次或换机分段 |
| 系统留痕 | 哪个账号何时做了什么修改 | 与纸面检验人员、实际检验时间分开 |

生产批按共享号＋完整型号识别，只去首尾空白，保留大小写、内部空格及标点；不做模糊归并。同号不同型号、同型号不同号分别建批。NORMAL/SAMPLING 共用同一生产批 ID，在工序填报组、单据占用和统计中分开。

同一生产批、工序、检验类型内，空检验批号代表整批；具名批号代表本工序分批。整批单与分批单互斥，具名批号唯一，取消后释放占用并可重用批号。新建与修改必须明确区分，不能以同号自动覆盖已有检验单。

## 3. 必须支持的业务场景

### 3.1 独立分批与提前流转

同一生产批 QS-001／型号 X，可出现：

| 工序 | 检验批号 | 机台 | 检验量 | 合格量 | 不合格量 |
|---|---|---|---|---|---|
| A | a | M01 | 400 | 390 | 10 |
| A | b | M01 | 350 | 340 | 10 |
| A | c | M02 | 250 | 240 | 10 |
| B | c | M03 | 600 | 588 | 12 |
| B | d | M04 | 360 | 352 | 8 |

A 合计 1000/970/30，B 合计 960/940/20。录入 B 不需要选择它来自 A 的哪一批；不按比例分摊，不把两个 c 自动关联。A-b/A-c 尚未完成或尚未录入时，B 仍可保存。工序间数量不同不阻断，也不要求填写损耗凑平。

### 3.2 现场分次填与集中补录

同一检验单可先填部分栏目，随后按单据 ID 补充。未提交字段保持原值；明细数组提交时完整替换。事后集中录入可逐张或批量新建，使用相同模型与校验。不能为集中录入另设一套事实来源。

### 3.3 更正与取消

将 A-a 从 400/390/10 改为 400/380/20，保存后 A 立即变为 1000/960/40；B 仍为 960/940/20。保留 A-a 的前后版本，不要求重新登记 B，不扣减后序、不冻结任何工序。

录错或重复单据可逻辑取消，必须填写原因。取消立即退出当前统计，内容和历史继续可查；取消不证明实物被追回或退还。误把真实新检验当作更正会丢失业务含义，因此重复检验/返工应另行确认，不能靠改历史冒充新增产量。

## 4. 填报内容

完整字段含义和 35 类缺陷编码见[字段目录](fields.md)，参考值见[参考资料](reference-data.md)。以下内容都须在当前文档体系中明确存在：

| 范围 | 必须保留的内容 |
|---|---|
| 纸面表头 | 计量单位“片”、送检人/时间、检验人/时间、操机员、交接员 |
| 身份与设备 | 共享表单号、完整型号、工序、检验批号、机台号、检验类型 |
| 样品信息 | 原文；项目、型号、规格、大小、左右五项结构化内容 |
| 计数 | 检验量、合格量、不合格量；服务端派生良率 |
| 缺陷 | 35 类 × 凹面/凸面/双面，每格为该类缺陷镜片数量 |
| 数量变化 | 类型、方向、可未知数量、原因、可未知发生日期/时点 |
| 备注与证据 | 行/单据备注、每次保存版本、操作者与系统时间、取消原因 |

纸面人员按文字记录，不能用登录用户代填。系统操作者来自会话。样品原文与结构化字段分别保存，辅助解析不改原文；原文录错时只能显式更正并保留旧版。参考清单不匹配照常保存。

只填写原始串、不做结构化拆解是合法录入方式；项目 M1/M2 必须有可录入的字段，但不要求每次保存已填。MONOC/BINOC/Rx 等辅助属性含义未明确，不升格为必填或统计分类。

每单固定一个检验批次/机台/纸面人员组合，现场检验批次内部不再分段。机台可以在不同单据复用。明细多行不用于表达人员设备切换；录错设备或人名属于内容更正，不表示新增执行段。

纸面单位是计量单位，仅允许“片”。前端固定传值，后端独立校验；其他单位或部门文字拒绝。未知可以暂存并提示缺项。用户所属部门独立保存，不能替代计量单位；所有数量不做多单位换算。

## 5. 保存、版本和状态

### 5.1 保存即生效

新建成功即形成当前内容版本。以后每次成功保存追加完整版本，并原子替换当前指针；已归组且有效的单据立即以最新版参与统计。旧版只用于历史，不与新版叠加。若修改失败，原内容和原统计保持。

对象状态采用有效/取消两种业务状态。资料缺项不产生另一套待发布状态。缺少生产批身份/工序时允许保存未归组记录，可读取历史，但不进入分组统计；绑定后立即以当前版统计。

每次更正记录操作人、系统时间、前一版本与可选原因；取消原因必填。所有登录用户可更正同检验类型的他人单据，管理员也受自身类型限制。不因后序已经存在而禁止修改前序。

### 5.2 补丁与未知值

- 字段不传保持；标量 null 清为未知；有值写入。0 是明确值。
- 对象递归合并；计数对象整体 null 清其全部项目，空对象不改。
- lines 与 quantity_changes 提交时完整替换；[] 清空；null 拒绝；不按行号偷偷合并。
- 归组身份不能随内容补填改变。已归组的组/批号误录，取消后明确重建；禁止无审计地移单或合批。
- 每次修改须带预期对象版本，冲突提示用户重新核对。成功重试不得重复生成内容版本或累计数量。

### 5.3 填报结束与资料完整度

is_complete/missing_fields 只描述资料是否齐全，不能表示审批、生产结束或实物流转完成。依次检查工序、单位（合法 ID 或文字任一）、检验人、样品原文、至少一条明细；缺项只提示，不限制保存或统计。未知计数另有统计完整性，不加入这五项判据。

工序组支持结束/重新开放，标记表达“本工序本类型不再新增单据”的填报意图。结束仅限制新增及未归组单绑定，已有单仍可补填、更正、取消；不检查资料完整度，不自动认定整生产批结束，不推导预计批次数或最后一道工序。各工序组互不关闭彼此。

## 6. 计数、缺陷与数量变化

### 6.1 唯一统计来源

表头填报的 counts.total_qty、counts.qualified_qty、counts.defect_qty 是检验量、合格量和不合格量的唯一统计来源，良率也仅由表头计数派生。明细行计数只求合计进行核对，不回填、覆盖或补齐表头；表头未知时，即使明细完整也保持未知。仅修改明细不改变表头统计值。

不另设纸面数量声明或其独立原始值字段，不存储或返回 declared_counts。表头与明细有可比较差异时保留双方内容并提示，不阻断合法保存。缺陷分布仍取明细中的缺陷格；本规则不取消缺陷统计、数量变化说明或每次保存的历史版本。

未知不补零，所有汇总同时返回已知部分、未知数量与完整性。完整可比范围内才计算良率：合格量合计÷检验量合计×100%，保留两位小数；不平均单张百分比。分母为零/未知、分子未知或超过分母时返回 null 与原因。

缺陷总和可以超过不合格量，不推导唯一不良件数。双面与单面不做未经确认的去重。某一格未知时不将其当成零，缺陷统计须体现不完整程度。

### 6.2 数量变化

允许只填写原因而数量未知。LOSS/ADJUSTMENT/OTHER 及方向分别保留。损耗条目不自动扣改本单 counts，也不改变后序计数。修订只统计当前版本，取消排除整单。SAMPLING 抽检禁止 LOSS，前端和后端都须拒绝，不保留可通过 API 绕过的入口。

不根据工序差额生成损耗，不将不同单的同原因说明自动认定为不同实物事件。报表称为“声明数量变化”，不能称准确库存流水。

## 7. 查询与报告

### 7.1 日常查询

支持按生产批身份、工序、检验类型、批号/整批、机台、纸面人员、单位、样品五项、原文关键字、系统创建/保存人、日期、取消状态及资料完整度查询。组合筛选使用 AND。列表分页，详情返回完整内容、105 格缺陷与留痕，不把一单多个历史版本列成多张当前单据。

历史查询可取任一明确内容版本，对比两个版本的字段/明细/数量变化。日志可按对象、操作人和系统时间查找。未填完整清单可通过同一列表 incomplete 条件获得；样品待拆解清单通过核心字段缺失条件获得，不能拿解析缓存代替业务清单。

### 7.2 生产批当前/历史时点报告

以某个系统时点还原该批已经存在的工序组、单据状态和当时当前版本；显示工序/类型分区、整批/分批单、填报状态、资料缺项、数量与良率。报告须携带实际版本集合、系统时点和事件序号。

后来的补填、取消、目录改名或组状态变化不得污染过去报告。系统时点不是纸面检验日；同秒内按事件序号固定视图。历史起点之前无证据则明确不可还原，不能从今天的状态反推。

### 7.3 工序日期范围报告

某工序在指定时间范围内可跨生产批查询，也可限定某批。返回分页单据和整个筛选范围的统计，分页不改变小计。取消资料可展示但不计有效结果。日期筛选使用当前版本的业务日或单据系统创建时间，不将范围查询冒充过去系统时点。

未知业务日不落入已知日期区间，另列数量；不得用创建时间补齐。正常/抽检分开统计，ALL 按类型分区。不存在跨类型混合良率。

### 7.4 通用统计与工作量

支持按生产批、工序、批号/整批、机台、单位、纸面人员、样品五项、系统创建/保存人、业务日/月组合分组，返回单据数、计数、良率、缺陷分布及数量变化。分组键用结构化对象，不用拼接字符串造成碰撞。

按纸面检验人汇总的是登记的检验量；按系统账号汇总的是录入归属或保存动作数，两者名称明确。跨工序数量相加只能称检验工作量，同件产品经过多工序可能重复计入。生产批报告不提供全流程良率、准确产量、实物去向或召回范围。

## 8. 账户与共享资料

本地账号密码登录、退出、本人改密、管理员创建/启停/重置密码及设置管理员。账号停用不删除其历史。NORMAL/SAMPLING 账户只能写自身类型，管理员无例外；所有登录用户可读两类、可改同类他人单据。登录返回固定填报标记，类型变更撤销旧会话并清旧幂等结果，不改原密码或已存单据类型。

工序、样品维度和参考部件号是可维护共享资料；计量单位固定“片”，其目录只读。字典修改不改历史版本；参考清单缺失不阻断填写。新工序可登记后使用通用模板，无固定路线和专用模板门槛。

样品解析支持原文输入、结构化建议、未知/冲突提示、人工确认与缓存复用。置信度不表示质量合格率，不作为业务保存条件。

## 9. 非功能要求

| 范围 | 要求 |
|---|---|
| 弱网 | 写请求幂等；断线原键原文重试不重复保存 |
| 并发 | 版本检查防覆盖；同一占用范围竞争仅一方成功；批量任一失败整体回滚 |
| 一致性 | 保存、当前版本、统计资格、防重占用、审计和幂等结果同事务 |
| 安全 | 登录及服务端授权、强密码哈希、可撤销会话；操作人不取自请求正文 |
| 留痕 | 每次内容保存及状态动作可查；无普通物理删除入口 |
| 双库 | SQLite/PostgreSQL 的 null、唯一性、事务、日期与统计语义一致 |
| 日期 | 规范日期/时点、精度不伪造、Asia/Shanghai 业务归日，不另存日期原文 |
| 性能 | 数十人并发；目标单笔 P95 <500ms、千笔条件查询 P95 <2s，须实测 |
| 备份 | 每日一致备份、保留 30 天；记录保留期与 RPO/RTO 待部署确认，未确认前不自动删记录 |

## 10. 明确的能力边界

无跨工序检验批次谱系、来源分摊、产出预占、库存/在途余额、精确召回、单片去重、全流程物料平衡或良率；无流程审批。更正 A 不触发 B 扣量、冻结或重新填写。

复检/返工轮次、跨生产批混料、生产批合并、身份改键和产品整体结束未有确认规则，不能用普通编辑隐式实现。导出/打印/历史导入作为低优先级计划，文件格式和映射在实施前确认。未登记的工序不等于未生产，填报进度不等于实时生产进度。

## 11. 验收场景

| 编号 | 场景 | 应有结果 |
|---|---|---|
| AC-01 | 同号同完整型号跨工序录入 | 同一生产批；同号不同型号或反向组合不误合批，类型在组内区分 |
| AC-02 | A-a/b/c 与 B-c/d | 五张独立单据；后序先录可成功，无来源选择 |
| AC-03 | A 未全部完成即录 B | 成功，不检查前序余额或关闭状态 |
| AC-04 | 新建与补填 | 新建明确产生单 ID；补填明确定位已有 ID，不以共享号覆盖 |
| AC-05 | 分三次补栏目 | 不传保持、null 未知、0 明确零；每次形成完整可查版本 |
| AC-06 | 修改 A-a 数量 | 保存立即更新 A；B 不变；旧时点仍是旧数量 |
| AC-07 | 修改失败/版本冲突 | 当前内容和统计不变，不产生半笔历史或成功缓存 |
| AC-08 | 取消有效单 | 当前统计立即排除；历史、原因、操作人仍可查 |
| AC-09 | 弱网/批量竞争 | 原键重试只成功一次；批量任一失败全部回滚 |
| AC-10 | 未知与零 | 汇总显示已知部分和缺量，未知不补零；0 分母良率 null |
| AC-11 | 多缺陷重复计数 | 保存并提示，缺陷分布不声称唯一不良数 |
| AC-12 | 样品解析失败或人工改结构化值 | 原文不变；参考缺项不阻断；项目不能从图号猜出 |
| AC-13 | 纸面检验人与代录账号不同 | 两者分别保存，按人统计不会混用 |
| AC-14 | 仅写损耗原因 | 数量 null 可保存；不自动扣 counts，不生成跨工序处置 |
| AC-15 | 业务日与录入日不同 | 日期口径显式，未知日不拿创建日补齐 |
| AC-16 | 只知日期/准确时点 | 不补造零点；准确时点 UTC 存储并按业务时区归日 |
| AC-17 | 同秒多次保存/取消 | 历史事件序号可固定同一视图；后续事件不污染 |
