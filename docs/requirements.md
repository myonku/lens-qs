# 无纸化检验台账 — v2 正式需求

版本：2.0.0。更新：2026-11-04。本文为本次实现基线，运行结果记录在 [发布记录](v2-release.md)。

## 1. 业务模型与保留边界

本工程交付后端。产品批由共享表单号与完整型号识别，仅去首尾空格，不模糊合批。产品批→按工序与检验类型隔离的填报组→检验单→不可覆盖内容版本；每道工序独立分批、独立填报，允许后序先录，不建立跨工序来源/余额/冻结。

空批号表示当前工序整产品批范围；同组同类型内，整批重复、分批重复、整批/分批混用拒绝。初始草稿也占用，取消释放。机台与纸面人员随内容版本保存，实际检验人员与系统账户分开。

保留所有纸面栏目、样品原文与五个核心项、35×3 缺陷、可空正式计数与纸面声明、可未知数量的损耗/数量变化原因。counts 是唯一正式统计来源，缺失不补零。正常与抽检共用内容结构，统计按类型隔离；抽检 LOSS 前端拦截，后端只做通用校验并保留原始证据，抽检损耗汇总不计 LOSS。

## 2. 账户与填报权限（本次新增）

账户增加 account_type=NORMAL/SAMPLING，已有账户迁移为 NORMAL。管理员标记 is_admin 独立，管理用户不意味着可以越过填报类型边界。两类账户均可读取正常/抽检资料，写入仅限自身类型：创建工序组/未归组草稿、绑定、保存、发布、取消和关闭/开放组均须校验，批量任一越权整批失败。

登录及 me 返回 account_type 与 submission_inspection_kind（相同枚举），前端据此固定本次账户的填报标记，不提供普通切换入口。未传 inspection_kind 时后端按账户补齐；显式相反标记，或访问相反类型的组/单写入口，返回 403 inspection_kind_forbidden。前端标记不能代替服务端权限检查。

仅管理员可创建/变更账户类型。类型变更清除该用户旧幂等结果并使会话失效；每笔事务内再次读取账户状态与类型，禁止通过旧 token、旧幂等结果或省略标记绕过边界。共享产品批不属于单一类型，两类均可新建。

## 3. 保存与生命周期

新建只存草稿；缺身份可未归组保存，发布前必须归组。PATCH 递归合并对象，不传保持、null 清未知；数组整组替换，[] 清空、null 拒绝。绑定后组/批号/类型不可普通修改。保存追加内容版本，强制 expected_version；正式修订草稿发布前不替换当前正式版。发布、取消、关闭/开放推进对象版本；修订发布、取消及组状态变更须原因。初始草稿未处理时不能关闭组，已发布单的修订草稿不阻止关闭。关闭后仍允许已有单修订/取消。

## 4. 报告新增需求

1. 指定系统时间点某产品批所有工序的填报状态：返回当时各组状态、整批/分批单、当时草稿与正式数据、版本 ID、系统计算良率、正式小计和初始/修订草稿数。之后保存、发布或取消不得污染之前时间点。时间点指系统留痕时间，不是把纸面日期筛选冒充历史回放；秒内按审计事件序号排序，包含截止秒的全部事件。
2. 指定时间范围内某工序的全部填报：可不限定或限定 product_lot_id；返回分页填报资料与全筛选范围的正式小计、分产品批/类型汇总、良率与实际版本集合。草稿/取消明确列示但不混入正式小计。默认业务检验日，日期范围包含两端；可用系统 created_at 时点范围 [from,to)。未知业务日单列数量，不用创建日期补齐。

两接口默认 NORMAL，可选 SAMPLING/ALL。ALL 分区返回，没有跨类型混合数量/良率。良率为完整可比范围内合格量÷检验量，分母未知/零或分子未知/超过分母时 null，保留原因。跨工序合计只称检验工作量。

## 5. v2 正式切换与清理

所有业务及共享账户/字典/解析接口统一 /api/v2，不保留旧路径别名、旧按号覆盖、旧统计和旧幂等中间件。未版本化 /api/* 请求返回 404。删除旧实现、旧验收脚本、迁移暂存/人工导入代码及双写域开关，历史文档只留 archive 与历史施工记录。

保留已发布迁移 0001–0005，新增迁移完成账户扩展和旧表删除，保证已有环境可向前升级。该切换会删除旧 forms/明细/历史/旧幂等/迁移暂存数据，旧测试数据已获业务方授权清除。现有账户 ID、密码哈希、字典保留。v2 测试数据通过显式维护命令清理，不在每次服务启动时清空。清理前保留可恢复备份；不推断本地之外的部署环境已切换。

日期/时点继续双库 TEXT：YYYY-MM-DD 与 UTC 秒精度 RFC3339；原文独立，Asia/Shanghai 归日。不纳入跨工序谱系、自动库存、复检轮次、产品批合并、审批、多租户与前端工程。

## 6. 验收基线

| 编号 | 场景及结果 |
|---|---|
| AC-01 | 同号同完整型号跨工序归一批；同号不同型号、同型号不同号分开 |
| AC-02 | A-a/b/c 与 B-c/d 共存，B 可先录；不出现来源分配或跨工序数量门槛 |
| AC-03 | 空批次四种写法归一整批；同组再次新建、整批/分批混用返回对应 409 |
| AC-04 | 同单 ID 补填/修订允许；同分批号新建冲突，新批号可追加；不同组同名批号合法 |
| AC-05 | 草稿也占用范围；取消保留历史并释放占用；有残余分批时仍不能建整批单；关闭组拒绝新增 |
| AC-06 | 两个并发整批请求或整批/分批竞争仅一方成功；批量内部冲突整批回滚；幂等回放不重复计数 |
| AC-07 | A-a 更正 400/390/10 为 400/380/20，仅 A 及相关分组改变，B 保持原结果 |
| AC-08 | 修订草稿不替换旧正式结果；发布/取消与统计一致；旧报告可找到实际版本集合 |
| AC-09 | 未填与零分开；无完整分母合格率为 null；纸面声明差异、重复缺陷不冒充准确产量 |
| AC-10 | 日期字符串格式统一，非法日期拒绝，日期不补零点，时区归日正确，原文保留，SQLite/PostgreSQL 行为一致 |
| AC-11 | 损耗可只填原因、数量未知；更正不重复计入，不由工序差值自动扣改结果 |
| AC-13 | 同产品批同工序的正常单与抽检单可各自使用同批号或空批次；各类型内仍检查重复/混用，正常组关闭不阻止抽检独立登记 |
| AC-14 | 抽检无需正常单 ID，使用相同表单和生命周期；抽检修订/取消不改变正常单、正式统计或进度；统计明确按类型隔离 |
| AC-15 | 前端抽检表单有标记并拦截 LOSS 损耗提交；后端无抽检专属损耗屏蔽，通用类型/数量校验照常；普通表单功能不受影响 |
| AC-12 | 正式切换保留账户/字典；旧测试单/历史在备份后清除，不再保留待核对导入流程 |
| AC-16 | 抽检账户缺省自动 SAMPLING；相反标记及跨类型新建/绑定/修改/发布/取消/关组 403，管理员也不能隐式绕过；批量越权无部分写入 |
| AC-17 | 登录/me/用户管理返回账户类型，类型变更使旧会话和幂等结果失效，原密码不变 |
| AC-18 | 截止时点还原首次草稿、发布、修订草稿、修订发布、取消与组关闭/开放；后续变化不改旧时点结果，同秒按事件序号可追溯 |
| AC-19 | 工序范围报告支持跨产品批与限定批、分页资料与全量小计，草稿/取消不计正式；日期/类型边界正确，未知不补零 |
| AC-20 | 新建库/旧库升级后仅有 v2 业务表和路由；旧代码/开关/脚本删除，账户密码与字典保留；本地测试数据清理和迁移可复验 |
