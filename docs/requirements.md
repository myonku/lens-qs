# 无纸化检验台账 — 需求基线

版本：v2.0-draft.2。日期：2026-11-04。状态：文档修订完成，设计建议待评审，v2 业务未实现。

依据：[归档 v0.3 草案](../archive/2026-11-03/rebuild-draft-v0.3.md)与本轮追加说明。当前进度及待确认项统一见[重建计划](rebuild-plan.md)。本文取代旧需求的工作基线，不把设计建议写成业务确认。

## 1. 定位与范围

系统是按产品批组织的无纸化检验台账，支持现场分次填写、事后集中代录、检索、修订和统计。本期交付后端及接口，页面描述仅说明调用场景。无审批流程；明确发布本批结果不代表审批。

已确认的业务边界：

| 编号 | 规则 |
|---|---|
| R-01 | 产品批由贯穿流程的**共享表单号＋完整样品型号**识别；只同号或只同型号不能归成一批 |
| R-02 | 每道工序自行分批；一张检验单对应本工序一个最小检验单位，批内人员与设备固定；设备可承接多个批次 |
| R-03 | 同产品批的前序 a/b/c 可以混合，再由后序分成 c/d；同名批号不表示同一实物，不记录来源分配 |
| R-04 | 各工序可异步填报、先录后序再补前序；不要求前序全部结束，不按跨工序数量差异阻断 |
| R-05 | 每批损耗及数量变化原因保留，可只说明原因而数量未知；不从工序差额自动生成损耗 |
| R-06 | 全部纸质既有栏目保留；实际检验/纸面人员与系统录入用户分别记录 |
| R-07 | 样品原文逐字保留，解析不改写原文；五个核心拆解项为项目、型号、规格、大小、左右。参考部件号仅辅助 |
| R-08 | 日期/时间继续按字符串存储，SQLite 继续受支持；撤销 v0.3 的原生日期列、因日期要求切换数据库的前提 |
| R-09 | 对无需拆分检验批次的工序，未填批次即**整产品批检验**，不是“待填批号”或匿名分批；同产品批同工序后续提交须校验 |

R-09 的“整批”指该产品批在**当前工序**的整批检验，不代表所有工序，也不自动证明现场采用全检。空批次与抽检/全检口径是不同问题。

不纳入：跨工序子批次谱系、交接扣量、来源余额、在途库存、自动物料平衡、精准下游影响定位、单片级去重、设备自动采集、多租户与复杂审批。跨原始产品批混料、返工/同工序多轮执行待另行确认。

## 2. 身份与单据

- `ProductLot`：共享身份；内部 ID 稳定，`shared_form_no + sample_identity_key` 唯一。
- `OperationGroup`：同产品批的某工序填报组，按检验类型分别组织，暂不表达同类型工序的重复执行轮次；不预设必须经过哪些工序。
- `InspectionSubmission`：一张整批单或一个具名分批单；身份与版本内容分离。
- `SubmissionRevision`：计数、缺陷、设备、纸面栏目、业务日期、数量变化与修订原因。当前有效正式版本只取一个。

完整身份型号用独立字段 `sample_identity`，不得直接使用解析器的 `sample_model=VID2` 等片段替代。规范化暂仅去首尾空白，保留大小写、内部空格及标点；不做模糊合批，规则待现场样例确认。

缺共享身份或工序时可保留未归组草稿；正式发布前必须明确归组。已有单据的补填/更正使用单据 ID，取消“共享表单号相同就更新”的隐式覆盖。

## 3. 批次规则（本轮重点）

已确认的是 R-09 的业务语义。以下是落实“后续提交做出校验”的**保守设计建议**，作为本版拟定契约；是否需要替代流程见待确认项 Q-02。

### 3.1 空值与唯一范围

新建时 `batch_no` 不传、`null`、空串或去首尾空白后为空，统一为 `null`，`scope=WHOLE`。有非空批号为 `scope=SPLIT`；如 `0`、`未分批` 是非空文本，不作为整批别名，调用方应提示使用留空表达整批。

唯一及互斥范围是 **同 product_lot_id＋同 operation_group_id**。不同产品批、不同工序的同名批次不冲突。具名批号暂仅去首尾空白，大小写保持不同；不通过日期、机台或人员差异绕过重复检验单校验。

### 3.2 后续新建判断表

“占用中”包含已归组的初始草稿、正式单及其修订草稿；取消单保留历史但释放占用。

| 当前工序组占用 | 后续新建 | 拟定处理 |
|---|---|---|
| 无占用 | 空批次 | 建立一张整批单 |
| 无占用 | 具名 a | 建立分批单 a |
| 整批单 | 再次空批次 | 409 `whole_submission_exists`，返回原单 ID；补填应修改原单 |
| 整批单 | 具名 a | 409 `batch_scope_conflict`，防止整批与分批重复统计 |
| 分批 a/b | 空批次 | 409 `batch_scope_conflict`，不能再加一张整批合计原始单 |
| 分批 a/b | 具名 a | 409 `batch_no_exists`，返回原单 ID |
| 分批 a/b | 新批号 c | 允许；不要求 a/b 已结束 |
| 任意 | 同一原请求的幂等重试 | 回放原结果，不再执行新建判断 |

上述冲突是身份和统计完整性约束，不能通过 `enforce=warn` 绕过。检查必须在服务端及事务内完成，不能只由页面预查。

### 3.3 补填、取消与变更方式

按原单 ID 保存草稿或追加正式修订不算新增批次。绑定工序组后的 `batch_no` 和归属不接受普通内容 PATCH 修改；录错时本期拟采用“取消原单＋明确新建”，保留原因和关联提示。

同一工序组只能有整批占用或分批占用之一。取消最后一张占用单后，开放的工序组可重新选择整批/分批方式；仍有任何占用单时禁止切换。取消、新建、发布、批量写入均执行相同检查。工序已结束时新增需先重新开放，更正已有单不受此限制。

此设计不能自动识别“换了新批号但实际重复检验”的实物重复；真实复检/返工不允许靠新批号冒充新增产量。

### 3.4 抽检（2026-11-04 新增确认）

每道工序均可登记抽检，使用与正常检验相同的表单内容，仅增加“抽检”标记。抽检与正常检验之间没有来源、关联单、数量分摊或结果依赖；可独立创建、填写、发布、修订和取消，无需先有正常检验记录。

设计采用 `inspection_kind=NORMAL/SAMPLING`（正常检验/抽检）。批次重复、整批/分批互斥以及工序开放/结束均在各类型内独立判断：同产品批、同工序、同批号可以各有一张正常单和抽检单，两张空批次整批单也可分别存在。类型不改变“批号为空表示本工序整产品批范围”的语义；抽检整批范围不等于检验了全部实物。暂沿用同类型内的现有批号规则，真实重复抽检的轮次规则并未因此引入。

抽检不填报损耗。按业务方要求，前端负责阻止抽检提交损耗条目（`quantity_changes.kind=LOSS`）；后端复用同一 DTO、字段目录及通用校验，不新增针对抽检的损耗字段屏蔽或拒绝规则。不新增抽检专用页面/表单模板，仅在普通表单显示抽检标记。

正常流程的数量、良率、损耗和进度不纳入抽检记录；抽检可单独查询统计，不能与正常结果相加推导产品数量或总体良率。此处是记录类型标记，不是抽样方案、抽样比例或自动抽样规则。

## 4. 表单内容与填写规则

原有栏目一个不减：单位（`paper_unit_id/paper_unit_text`）、送检人、送检时间、检验人、检验时间、操机员、交接员。保留检验工序、检验量、合格量、不合格量、服务端合格率，以及样品原文与结构化项。机台号、批次及数量变化是新增项。

缺陷目录沿用 [formfields.go](../backend/internal/formfields/formfields.go) 的 35 类×凹面/凸面/双面 105 格；类别与中文名见[接口文档](api.md)。原纸面 117 栏是显示口径，非新模型字段总数，合格率是派生只读项。表格下方手写率值行（如 `A：100%`）仍不建字段。

| 项目 | 拟定规则 |
|---|---|
| 草稿 | 允许缺内容、无数量、未归组；未知字段/非法类型/负计数/非法规范日期仍拒绝 |
| 字段补丁 | 未传不改，`null` 清为未知，有值写入；`0` 是已知零，不等于未知 |
| 明细 | `lines` 不传保持；传数组整组替换，`[]` 清空；明细不是更小检验批次 |
| 正式计数 | `counts` 是唯一正式计数源；纸面合计存 `declared_counts`，行合计仅核对，不互相静默覆盖 |
| 完整度 | `is_complete/missing_fields` 是提示，不能等同本批结束或阻断缺项草稿 |
| 发布 | 人工明确本批结果已登记结束，允许缺非关键纸面项；数量未知仍明确标识，不补造 0 |
| 修订 | 当前正式版本持续生效，修订草稿发布后才替换；发布修订和取消必须填原因 |

抽检作为独立记录类型已确认；正常检验与抽检各自的单批数量定义及“合格＋不合格＝检验量”适用范围仍待确认，当前拟警告；缺陷子项可因同片多类缺陷重复，不据此推导唯一不良件数。损耗不等于不合格品，数量变化不自动扣改检验计数。

时间以 TEXT 存储：日期 `YYYY-MM-DD`，准确时间点 UTC `YYYY-MM-DDTHH:mm:ssZ`。只知日期不造时刻，未知为 `null`；旧纸面日期原文另存。新输入规范、时区与查询规则见[设计](design.md) §6。

## 5. 状态、统计与权限

单据为 `DRAFT/PUBLISHED/CANCELLED`；已发布单可以另有修订草稿。工序组为 `OPEN/CLOSED`，独立于整批/分批方式。前序修改只改变本工序及相应设备、人员、日期分组结果，不冻结或改写后序。

正式汇总取每张未取消单的当前正式版本一次；草稿、旧版、取消单分开。缺未知计数时返回已知部分、未知单数与不完整标志，不当作完整合计。工序合格率取完整可比范围内的合格量合计÷检验量合计，不平均各单百分比。跨工序相加只能称检验工作量，不能称产品总量。

产品批总览按工序分区，展示已登记/已发布单数、修订草稿及工序是否关闭；不能仅凭录入记录推断实物位置。原始单与其只读汇总不可再次相加。

沿用本地账号、管理员/普通用户两级；必须登录。普通用户默认读写业务，管理员额外管理用户。正式更正暂按普通用户可操作且强制原因和审计设计，更正权限是否收紧见 Q-05。不新增审批角色。管理员账户、密码哈希、字典与历史记录需保留。

## 6. 验收基线

| 编号 | 场景及结果 |
|---|---|
| AC-01 | 同号同完整型号跨工序归一批；同号不同型号、同型号不同号分开 |
| AC-02 | A-a/b/c 与 B-c/d 共存，B 可先录；不出现来源分配或跨工序数量门槛 |
| AC-03 | 空批次四种写法归一整批；同组再次新建、整批/分批混用返回对应 409 |
| AC-04 | 同单 ID 补填/修订允许；同分批号新建冲突，新批号可追加；不同组同名批号合法 |
| AC-05 | 草稿也占用范围；取消保留历史并释放占用；有残余分批时仍不能建整批单；关闭组拒绝新增 |
| AC-06 | 两个并发整批请求或整批/分批竞争仅一方成功；批量内部冲突整批回滚；幂等回放不重复计数 |
| AC-07 | A-a 更正 400/390/10 为 400/380/20，仅 A 及相关分组改变，B 保持原结果 |
| AC-08 | 修订草稿不替换旧正式结果；发布/取消与统计一致；旧报告可找到实际版本集合 |
| AC-09 | 未填与零分开；无完整分母合格率为 null；纸面声明差异、重复缺陷不冒充准确产量 |
| AC-10 | 日期字符串格式统一，非法日期拒绝，日期不补零点，时区归日正确，原文保留，SQLite/PostgreSQL 行为一致 |
| AC-11 | 损耗可只填原因、数量未知；更正不重复计入，不由工序差值自动扣改结果 |
| AC-13 | 同产品批同工序的正常单与抽检单可各自使用同批号或空批次；各类型内仍检查重复/混用，正常组关闭不阻止抽检独立登记 |
| AC-14 | 抽检无需正常单 ID，使用相同表单和生命周期；抽检修订/取消不改变正常单、正式统计或进度；统计明确按类型隔离 |
| AC-15 | 前端抽检表单有标记并拦截 LOSS 损耗提交；后端无抽检专属损耗屏蔽，通用类型/数量校验照常；普通表单功能不受影响 |
| AC-12 | 迁移保留账户/字典/旧单/历史，无法判定身份或整批语义的数据进入待核对，不自动合并或正式发布 |

这是实施验收清单，本轮只完成文档检查，未执行 v2 业务验收。
