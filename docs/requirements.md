> **v0.2 主要变更**（依据业务方第二轮确认，详见 §2.2 与 §9）
> 1. **无审核流程**：用户保存即生效，不再设计 DRAFT/SUBMITTED/APPROVED 审批流。
> 2. **同表单号可多次录入、以最新为准**：同一表单号在不同阶段可能被分次填报（可能只填一部分），后录入**覆盖**先录入，系统只保留最新内容 + 追加式历史快照。
> 3. **样品信息以原始输入为准**：部件号清单只是**参考**，不能假定生产部门照该清单填写；`sample_raw` 为事实来源，`M1/M2`（项目）必须纳入结构化录入。
> 4. **送检人 / 操机员 / 交接员 / 下方手写率值**：属生产部门规章流程，**不在本期范围**。
> 5. **不良重复计数**（同一片镜片可能被计入多个不良类别）已确认存在，登记为 `【待定】`，本期按**警告**处理，不阻断提交。

> **标注约定**：`【确认】` = 业务方已明确说明；`【待确认】` = 尚未确认的假设；`【假设】` = 我方为保证可设计性先行的默认决定，评审可直接推翻；`【待定】` = 业务方已知问题并明确**延后处理**，本期只做记录不做解决。
>
> **字段命名约定**：本文档为便于阅读使用 `snake_case`（如 `sample_raw`、`form_no`、`entry_seq`）；
> 设计文档 §4 的 Prisma 模型使用 `camelCase`（`sampleRaw`、`formNo`、`entrySeq`）。**同一字段，仅命名风格不同**，无第二套字段。

## 1. 背景与目标

### 1.1 背景
镜片（含 KF / EVT 相关产品部件）在加硬等工序后需要进行表面质量检验，目前使用纸质表单《镜片表面质量检验记录表》逐批手写记录，存在以下问题：

- 纸质记录难以查询、统计与追溯（按批次、部件号、检验人、日期检索几乎不可行）。
- 手写内容不规范（如"一次加硬"被写在没有栏目名的空格里），无法结构化汇总。
- 不良分类（点伤 / 划伤 / 脏污 / 加硬点 / 垃圾点 × 凹面 / 凸面 / 双面）数据无法沉淀为质量分析依据。

### 1.2 目标
将纸质表单线上化，形成**可录入、可校验、可检索、可统计、可追溯**的检验记录系统：

1. 线上填报表单，字段与纸质表单一一对应，**不改变现场检验人员的作业习惯与判定口径**。
2. 样品信息支持"原始整体输入"与"拆解为多个可查询字段"双轨存储，**以原始输入为准**。
3. 提供一套可用的用户体系（账号、认证、角色、权限、审计）。
4. 同一表单号支持分阶段多次录入，系统始终保存**最新一次录入的内容**，并保留修改历史以备追溯。
5. 为后续的质量统计、良率趋势、不良分类分析留出数据基础。

### 1.3 非目标（本期不做）
- **不做审核/审批流程**：保存即录入生效（见 §5）。
- 不做镜片检验设备 / AOI 的自动数据采集与对接。
- 不做 MES / ERP / 图纸系统的集成（预留接口位）。
- 不改变检验判定标准本身（系统只记录结果，不做缺陷自动判定）。
- 不做多工厂 / 多租户架构（预留 `org_id` 字段但本期单组织）。
- 不处理生产部门规章流程中需手写的栏位：**送检人、送检时间、操机员、交接员，以及表格下方手写的率值行（如 `A：100%`）**（见 §2.2 B-9、B-10）。
- 不解决"同一片镜片被计入多个不良类别"的重复计数问题（见 §9 Q5，登记为 `【待定】`）。

## 2. 名词与业务口径

### 2.1 表单标题
**镜片表面质量检验记录表**

### 2.2 业务口径（业务方口述确认）

| 编号 | 口径 | 状态 |
|---|---|---|
| B-1 | 「样品信息」在纸质表单上是一个独立项目，但其内容包含**多项信息**（见 §4.2 分层） | 【确认】 |
| B-2 | 纸质表单上「单位」与「表单号」之间那个没有栏目名的独立空格，实际是一个**独立项目：工序**，只是表单没有印制该栏名 | 【确认】 |
| B-3 | 该空格中的手写内容为 **「一次加硬」**（此前我方误读为"1R 加硬"） | 【确认】 |
| B-4 | 不良分类（点伤 / 划伤 / 脏污 / 加硬点 / 垃圾点）下的每一个子格（凹面 / 凸面 / 双面）填的是**该类不良的镜片数量**（不是比例、不是缺陷个数） | 【确认】 |
| B-5 | 本次任务范围：把这张手写表单做成线上系统 | 【确认】 |
| B-6 | 「样品信息」的内容**与部件号（图纸号）清单有关系，但不能确定生产部门就是照着该清单填写的**（存在沟通/习惯差异）。因此**一律以表单上的原始输入为准**，部件号清单仅作为结构化参考 | 【确认】 |
| B-7 | 「项目（M1 / M2）」等信息**必须纳入**系统的样品信息结构化录入 | 【确认】 |
| B-8 | 业务方**无法确认** `MONOC / BINOC / Rx` 等部件号附加成分的含义，也不掌握更多确切信息（唯一确切来源就是那张表单照片）。因此这部分**做到"有冗余字段更好、没有也能跑"即可**，不作为验收条件 | 【确认】 |
| B-9 | **同一份表单（同一表单号）可能会被多次录入**（不同阶段可能只填一部分内容），**允许覆盖录入，系统只保留最新内容** | 【确认】 |
| B-10 | **不需要审核流程**：用户提交即视为录入生效 | 【确认】 |
| B-11 | 表格下方手写的率值（如 `A：100%`）属生产部门规章流程要求的手写内容，**与本期系统无关** | 【确认】 |
| B-12 | 同一片镜片**可能同时被计入多个不良类别**，即各子项之和可能大于不良品数量 | 【确认】【待定】 |

### 2.3 关键术语表

| 术语 | 含义 | 备注 |
|---|---|---|
| 工序 | 本记录对应的加工工序，如「一次加硬」 | 纸质表单未印栏名，线上系统必须补上 |
| 样品信息 | 部件/图号的原始书写形式，形如 `M2 S2 ND2 SMR` | 需双轨存储，见 §4.2 |
| 原始串（`sample_raw`） | 检验员在表单「样品信息」栏实际写下的整段内容 | **事实来源**，系统不得改写或"纠正" |
| 结构化字段 | 由原始串拆解出的可查询字段（项目/型号/规格/大小/左右 + 冗余） | 允许人工修正，修正不改写原始串 |
| 部件号（图纸号） | 参考清单中的规范编号，形如 `S1 - MD - R - VID2 - MONOC & BINOC`（序号 05~22） | **仅供参考**，不假定现场按此填写（B-6） |
| 录入次数（`entry_seq`） | 同一表单号被录入的序号，从 1 开始递增 | 覆盖录入产生，只保留最新为当前内容（B-9） |
| 覆盖录入 | 同一表单号再次保存时，用新内容替换当前内容的模式 | 旧内容进历史快照，见 §5 |
| 检验总数 | 本批次受检镜片片数 | |
| 合格品 | 检验合格的镜片片数 | |
| 不良品 | 检验判定为不良的镜片片数 | |
| 点伤 / 划伤 / 脏污 / 加硬点 / 垃圾点 | 五类表面不良 | 判定标准由业务方另行给出，见 §9 Q4 |
| 凹面 / 凸面 / 双面 | 每个不良类别下的三个计数维度 | 含义见 §9 Q5（`【待定】`） |

## 3. 用户与角色

### 3.1 角色定义

| 角色 | 代码 | 职责 | 关键权限 |
|---|---|---|---|
| 检验员 | `inspector` | 现场检验并按表单录入记录（可覆盖自己的记录） | 创建/覆盖/查看记录（本人）、查看统计（本人） |
| 管理员 | `admin` | 用户与字典维护、数据导出、历史追溯 | 用户管理、角色权限、字典维护、全量查询与导出、审计与历史查看 |
| 只读用户 | `viewer` | 质量/管理人员查阅与统计 | 只读查询、统计、导出（按授权范围） |

> 【确认】**不设审核员角色与审核流程**：用户保存即录入生效（B-10）。因此角色的目标不是"控制审批"，而是**控制录入范围与数据可见范围**。
> 【待确认】是否需要细分"质检主管"等角色，以及检验员能否覆盖**他人**录入的记录（当前设计：默认不能，需 `record:overwrite:any` 权限）。

### 3.2 用户体系需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| U-1 | 账号 + 密码登录，密码以强哈希（Argon2id 或 bcrypt）存储，禁止明文/可逆加密 | P0 |
| U-2 | 用户具备唯一登录名、姓名、工号、所属单位/部门、角色、状态（启用/停用） | P0 |
| U-3 | 首次登录强制修改初始密码；管理员可重置密码并强制再次修改 | P0 |
| U-4 | 登录失败次数限制与锁定（如 5 次失败锁定 10 分钟） | P1 |
| U-5 | 会话有效期 + 空闲超时；支持主动登出；移动端记住登录态 | P0 |
| U-6 | 角色-权限模型：权限点为「资源 + 动作」（如 `record:create`、`record:overwrite:any`、`user:manage`） | P0 |
| U-7 | 停用用户立即失去登录能力，但其历史记录保留并可见其姓名 | P0 |
| U-8 | 关键操作审计日志：登录、登出、创建/**覆盖**/作废记录、用户与字典变更，含操作人、时间、IP、变更前后内容 | P0 |
| U-9 | 管理员可为用户重置密码、启用/停用、调整角色 | P0 |
| U-10 | 个人可修改自己的密码与显示名 | P1 |
| U-11 | 数据可见范围：检验员仅见本人记录；管理员/只读用户见全部（可按单位过滤） | P0 |
| U-12 | **覆盖录入留痕**：任何覆盖操作记录操作人、时间与旧内容快照，可追溯"谁在何时把什么改成了什么" | P0 |
| U-13 | 【待确认】是否对接企业微信 / 钉钉 / LDAP / AD 单点登录 | P2 |

## 4. 功能需求

### 4.1 记录填报（核心）

#### 4.1.1 表头字段

| 栏目（对应纸质表单） | 系统字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| 表单号 | `form_no` | 文本 | 是 | 如 `M-260908-01`。系统的**记录主键**（同一表单号只有一条当前记录），支持自动生成与手工录入，见 §4.4、§5.2 |
| 样品信息（原始） | `sample_raw` | 文本 | 是 | 原始整体输入，逐字保留手写原貌；**事实来源**，系统不得改写（B-6） |
| 样品信息（拆解） | 见 §4.2 | 多字段 | 否 | 结构化轨；**项目（M1/M2）必须纳入**（B-7），其余尽量解析、可人工修正 |
| **工序**（纸质表单未印栏名） | `process` | 枚举 | 是 | 如「一次加硬」；**线上必须显式呈现为独立项目**（B-2、B-3） |
| 检验人 | `inspected_by` | 用户 | 是 | 默认当前登录用户 |
| 检验时间 | `inspected_at` | 日期时间 | 是 | 默认当前时间，可改 |
| 单位 | `unit_name` | 枚举 | 否 | 保留字段，选填 |
| 送检人 | `submitted_by` | — | — | **本期不实现**：属生产部门规章流程（B-9），仅在读与导出时以空值呈现 |
| 送检时间 | `submitted_at` | — | — | **本期不实现**（同上） |
| 操机员 | `machine_operator` | — | — | **本期不实现**（同上） |
| 交接员 | `handover_by` | — | — | **本期不实现**（同上） |
| 表格下方手写率值 | `manual_rate_note` | 文本 | 否 | 如 `A：100%`。**本期不实现业务含义**（B-11）：如需原样留档可存为无意义备注，或直接忽略 |
| （系统维护字段） | `entry_seq` / `entry_count` | 整数 | 系统 | 当前内容的录入序号 / 累计录入次数，见 §5.2 |
| （系统维护字段） | `last_saved_by` / `last_saved_at` | 用户/时间 | 系统 | 当前内容由谁在何时保存 |

> 【确认】送检人 / 送检时间 / 操机员 / 交接员 属生产部门规章流程要求的手写栏位，**与本期系统无关**，不再讨论其必填策略（B-9）。
> 【待确认】「单位」是否仍需录入？当前设计为**选填**字典项（便于按单位过滤统计）。

#### 4.1.2 检验明细

一行 = 一个批次的计数录入（纸质表单一行）。字段与纸质表格列一一对应：

| 列 | 字段 | 类型 | 约束 |
|---|---|---|---|
| 检验总数 | `total_qty` | 整数 ≥ 0 | 必填 |
| 合格品 | `qualified_qty` | 整数 ≥ 0 | 必填 |
| 不良品 | `defect_qty` | 整数 ≥ 0 | 必填 |
| 点伤-凹面 | `spot_concave` | 整数 ≥ 0 | 可选（默认 0） |
| 点伤-凸面 | `spot_convex` | 整数 ≥ 0 | 可选（默认 0） |
| 点伤-双面 | `spot_both` | 整数 ≥ 0 | 可选（默认 0） |
| 划伤-凹面 | `scratch_concave` | 整数 ≥ 0 | 可选（默认 0） |
| 划伤-凸面 | `scratch_convex` | 整数 ≥ 0 | 可选（默认 0） |
| 划伤-双面 | `scratch_both` | 整数 ≥ 0 | 可选（默认 0） |
| 脏污-凹面 | `dirt_concave` | 整数 ≥ 0 | 可选（默认 0） |
| 脏污-凸面 | `dirt_convex` | 整数 ≥ 0 | 可选（默认 0） |
| 脏污-双面 | `dirt_both` | 整数 ≥ 0 | 可选（默认 0） |
| 加硬点-凹面 | `hard_spot_concave` | 整数 ≥ 0 | 可选（默认 0） |
| 加硬点-凸面 | `hard_spot_convex` | 整数 ≥ 0 | 可选（默认 0） |
| 加硬点-双面 | `hard_spot_both` | 整数 ≥ 0 | 可选（默认 0） |
| 垃圾点-凹面 | `debris_concave` | 整数 ≥ 0 | 可选（默认 0） |
| 垃圾点-凸面 | `debris_convex` | 整数 ≥ 0 | 可选（默认 0） |
| 垃圾点-双面 | `debris_both` | 整数 ≥ 0 | 可选（默认 0） |
| （良率） | `pass_rate` | 计算值 | 系统计算，不手填，见 §4.3 |

> 【确认】每个子格填的是**该类不良的镜片数量**（B-4）。
> 【确认】同一片镜片可能被计入多个不良类别（B-12），因此**不能期待** `Σ15子项 = 不良品`（见 V-2）。

#### 4.1.3 校验规则

| 编号 | 规则 | 级别 |
|---|---|---|
| V-1 | `qualified_qty + defect_qty = total_qty` | 错误（阻断保存） |
| V-2 | `sum(五类不良的 15 个子项) = defect_qty` | **警告**（不阻断保存）。业务方已确认存在重复计数（B-12），本期仅提示"合计与不良品不一致"，留待 §9 Q5 解决 |
| V-3 | 各类别三子项之和 ≤ `defect_qty`；任一子项 ≤ `total_qty` | 错误 |
| V-4 | `total_qty > 0`；所有计数为整数，非负 | 错误 |
| V-5 | 良率 = `qualified_qty / total_qty × 100%`，保留 1~2 位小数；跨行/整单良率 = `Σ合格品 / Σ检验总数` | 计算 |
| V-6 | 检验时间不得晚于当前时间 | 错误 |
| V-7 | `form_no` 在系统中唯一（同一表单号只有一条当前记录）；同一表单号再次保存按 §5.2 **覆盖**处理，不产生第二条 | 错误（唯一索引兜底） |
| V-8 | 样品信息拆解字段与参考部件号清单不匹配 | 警告（允许保存，仅标记"待核对"，见 §4.2.4）。**不得因不匹配而阻断录入**（B-6、B-8） |
| V-9 | 结构化必填项（**项目 M1/M2**）为空 | 警告（可保存为"待补全"）【待确认：是否升为错误 —— 建议保持警告，避免现场被迫中断录入】 |

#### 4.1.4 录入交互需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| E-1 | 移动端优先：现场用手机/平板填报，数字字段唤起数字键盘，大按钮、大字号 | P0 |
| E-2 | 界面布局与纸质表单**视觉同构**（同一行、同一列顺序），降低培训成本 | P0 |
| E-3 | 计数实时联动：录入即可见良率与"合计校验"提示（合计不符即时标红） | P0 |
| E-4 | 支持"多行明细"：同一表单号下可录入多行计数（如分批抽检），默认 1 行 | P1 |
| E-5 | 草稿自动保存（断网/误退不丢数据）；本地缓存后恢复 | P1 |
| E-6 | 复制上一条记录 / 复制上一行，减少重复录入 | P1 |
| E-7 | **保存即生效**（无审核）；允许对同一表单号再次录入并**覆盖**，覆盖前需二次确认并展示当前内容 | P0 |
| E-8 | 按表单号打开时，若该表单号已有记录，直接进入"补填/覆盖"模式，并提示"当前为第 N 次录入" | P0 |
| E-9 | 字典项（工序、单位、样品信息分段）均可用下拉选择，支持新增（受权限控制） | P0 |
| E-10 | 打印/导出为与纸质表单一致的 PDF | P1 |
| E-11 | 覆盖后可查看"本次改了什么"（字段级差异），并可回看历史快照（权限控制） | P1 |

### 4.2 样品信息（重点需求）

#### 4.2.1 双轨存储

业务方明确要求样品信息**两类存储并存**：

- **原始轨 `sample_raw`**：整段原始输入，形如 `M2 S2 ND2 SMR`（示例按表单照片），逐字保留，永不改写。作为事实来源（source of truth）。
- **结构化轨**：系统录入时将原始串拆解为多个独立字段，用于查询、筛选、统计、分组。

原始轨不做任何规范化或纠正；结构化轨允许人工修正，且两者不一致时以原始轨为准，并记录差异标记。

#### 4.2.2 拆解字段与层级

业务方给出的层级（示例导向）：

```
项目        （M1 / M2）
 └ 型号     （VID1 RX / VID2）
    └ 规格  （S1 / S2）
       └ 大小（MD / SM）
          └ 左右（L / R）
```

同时，由业务方给出的部件号列表（§4.2.3）可看出还存在**两个附加成分**：

| 附加成分 | 取值 | 我方理解 | 状态 |
|---|---|---|---|
| 结构类别 | `MONOC` / `BINOC` / `MONOC & BINOC` | Monocular / Binocular（单目 / 双目），表示该部件适用的产品构型 | 【假设】【确认无法确认】 |
| 处方属性 | `Rx`（或写作 `RX`） | 处方镜（prescription），出现在 `VID1 Rx` 型号中 | 【假设】【确认无法确认】 |

> **重要（业务方第二轮确认，B-6 / B-8）**：业务方**只能确认"样品信息项的内容与部件号清单有关系"，但无法确认生产部门实际就是照该清单填写的**（存在部门间沟通/习惯差异），并且**无法确认** `MONOC / BINOC / Rx` 等附加成分的准确含义——业务方唯一确切的信息来源就是那张表单照片。
>
> 由此产生一条贯穿全局的设计原则：
> **① 以表单上的原始输入为准（`sample_raw` 为事实来源）；② 部件号清单与附加成分只作为"尽力而为"的冗余参考，解析不到、对不上都不得阻断录入、不得作为验收条件。**
>
> （原业务方表述："把已有信息做好即可……有冗余更好，但没有也能跑。"）

因此设计为：
- **五个核心拆解字段**：**项目（M1/M2）必须纳入表单并作为结构化录入项**（B-7）；型号 / 规格 / 大小 / 左右尽量解析并允许人工修正。
- **冗余（扩展）字段** `MONOC/BINOC` 与 `Rx`：尽力解析填充，解析不到留空，**不参与任何校验，不作为验收条件**（B-8）。

核心五字段（结构化轨）：

| 层级 | 字段 | 示例值 | 字典/取值 | 要求 |
|---|---|---|---|---|
| 1 项目 | `sample_project` | `M2` | M1 / M2 | **必须纳入**（B-7） |
| 2 型号 | `sample_model` | `VID2` | VID1 Rx / VID2 | 尽量解析，可人工修正 |
| 3 规格 | `sample_spec` | `S2` | S1 / S2 | 尽量解析，可人工修正 |
| 4 大小 | `sample_size` | `SM` | MD / SM / LG | 尽量解析，可人工修正 |
| 5 左右 | `sample_side` | `R` | L / R | 尽量解析，可人工修正 |

冗余（扩展）字段（**均可空、不校验、不作为验收条件**）：

| 字段 | 示例值 | 说明 |
|---|---|---|
| `sample_class`（结构类别） | `MONOC` / `BINOC` / `MONOC_AND_BINOC` | 可多选（一个部件可能同时适用单目与双目）；**含义未确认** |
| `sample_is_rx`（处方镜） | `true` / `false` | 型号含 `Rx` / `RX` 时为 true；**含义未确认** |
| `sample_drawing_no`（匹配到的参考部件号） | `S2 - SM - R - VID2 - MONOC` | 来自 §4.2.3 参考清单，**仅供参考** |
| `sample_drawing_seq`（参考清单序号） | `09` | 便于按清单序号查询 |
| `sample_unmatched_reason` | `raw_only` / `no_drawing` / `partial` | 未匹配原因，驱动"待核对"清单 |

> 【保留的设计提醒】层级顺序与字符串书写顺序不一致：业务方描述的层级是 项目 → 型号 → 规格 → 大小 → 左右，而参考清单中部件号的**书写顺序**是 `规格 - 大小 - 左右 - 型号 - 结构类别`（如 `S1 - MD - R - VID2 - MONOC & BINOC`）。系统以**字段**为准，**解析器按 token 集合识别而非按位置解析**。

## 5. 记录生命周期与覆盖录入

> **本节依据业务方第二轮确认重写**：无审核流程（B-10）；同一表单号可多次录入、以最新为准（B-9）。

### 5.1 设计原则："一表单号一当前记录 + 追加式历史"

**不再设计 DRAFT / SUBMITTED / APPROVED / REJECTED 审批状态机。** 保存即录入生效。

```
                ┌─────────────────────────────────────────────┐
                │  表单号 M-260908-01                          │
                │  ═══════════════════                         │
   第1次录入 ──>│  当前内容（v1 / entry_seq=1）  ← 可被覆盖      │
                │  样品信息、工序、计数明细、检验人、检验时间…   │
                └─────────────────────────────────────────────┘
                                │ 第2次录入同一表单号（可能只补一部分字段）
                                ▼
                ┌─────────────────────────────────────────────┐
                │  当前内容（v2 / entry_seq=2）  ← 唯一对外可见  │
                └─────────────────────────────────────────────┘
                                │
                ┌─────────────────────────────────────────────┐
                │  历史快照（只读、可追溯、不可编辑）            │
                │  history: v1 的完整内容 + 修改人 + 时间        │
                └─────────────────────────────────────────────┘
```

### 5.2 覆盖录入规则

| 编号 | 规则 |
|---|---|
| L-1 | 表单号是记录的唯一键：**一个表单号 = 一条当前记录**，无论录入多少次 |
| L-2 | 同一表单号再次保存 → **覆盖**当前内容（整体替换本次提交所包含的字段与明细），`entry_seq` 自增，`entry_count` 累加 |
| L-3 | 每次覆盖前，将**旧内容完整快照**写入历史表（含旧明细行、旧结构化字段、旧原始串），并记录修改人、时间、IP。历史**不可修改、不可删除** |
| L-4 | 覆盖采用**整体覆盖**而非字段级合并：未在本次提交中给出的字段，按"本次提交的完整表单"处理（前端在覆盖模式下会先载入当前内容，因此等价于"基于现状修改"）【设计决定，见 Q15】 |
| L-5 | 覆盖需 UI 二次确认，并展示"当前内容摘要"，避免误覆盖 |
| L-6 | 覆盖权限：默认仅**创建者本人**与管理员可覆盖；检验员能否覆盖他人录入的记录由 `record:overwrite:any` 权限控制【待确认】 |
| L-7 | 并发覆盖：以 `updatedAt` / `entry_seq` 作乐观锁；若打开页面后记录已被他人覆盖 → 保存时提示并展示差异，由用户决定是否继续 |
| L-8 | 记录**不做物理删除**；如需废弃用"作废（VOID）"标记并填写原因，作废记录默认不出现在统计中 |
| L-9 | 允许"分阶段只填一部分"：结构化字段与明细行均可为空提交（受 V-1 等强校验约束的必填计数除外，见 Q15） |

> 【待确认 Q15】"可能只填一部分"的具体口径：
> - (a) 允许保存**不完整的表单**（如只填了样品信息与工序、还没填计数）？→ 若允许，则 V-1（合格+不良=总数）在计数未填时需放宽。
> - (b) 还是每次录入都是一份完整的表单，只是不同阶段**内容不同**？
> - 当前设计取 **(b) 为默认**（每次都是完整有效表单，V-1 强校验），并为 (a) 预留 `is_incomplete` 标记与"待补全"清单。**请业务方确认**。

### 5.3 字段级的"最新内容"语义

| 内容 | 是否随覆盖更新 | 说明 |
|---|---|---|
| `sample_raw`、结构化字段 | 是 | 覆盖时整体替换；历史快照保留旧串（原始串也可能被重新书写） |
| `process`、检验人、检验时间 | 是 | |
| 计数明细行（全部） | 是 | 明细整体替换；旧明细进历史 |
| `created_by` / `created_at` | 否 | 首版创建者与时间**永不改变**，用于"谁最初开的这张表" |
| `last_saved_by` / `last_saved_at` | 是 | 指向当前内容的责任人 |
| `entry_seq` / `entry_count` | 递增 | 用于展示"第 N 次录入" |
| 审计与历史 | 只增 | 不可修改、不可删除 |

### 5.4 状态取值（极简）

| 状态 | 说明 |
|---|---|
| `ACTIVE` | 已录入生效（默认，唯一正常状态） |
| `VOID` | 已作废（逻辑标记，需权限与原因；保留全部数据与历史） |

## 8. 验收标准（初稿）

1. 检验员可在手机上于 60 秒内完成一条与纸质表单等效的记录录入并保存。
2. 样品信息支持原始串录入 + 自动拆解为 5 个核心字段（含**项目 M1/M2**）与冗余字段，且可人工修正；**修正与解析均不改写原始串**。
3. 按 `sample_size = SM`、`process = 一次加硬`、日期区间等条件可正确检索到记录（验证索引有效）。
4. 计数校验（V-1 阻断、V-2 警告）行为正确；良率计算与手工核算一致。
5. **同一表单号连续录入 3 次，系统只保留最新内容，历史快照可回看且能看出每次改了什么（字段级差异）**。
6. 用户体系可完成：创建用户 → 首次登录改密 → 按角色限制功能 → 停用用户后无法登录。
7. 任一记录的**每次覆盖**均可追溯（含操作人、时间、前后内容）。
8. 表单号并发生成 100 次无重号。
9. 导出的 Excel 与页面筛选结果一致（默认导出最新内容）。
