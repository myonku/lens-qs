# 重建迁移与日期文本规范化说明

版本：v2.0-draft.2。日期：2026-11-04。状态：迁移设计，**尚未执行盘点、迁移或切换**。

配套：[设计](design.md)、[API](api.md)、[实施计划](rebuild-plan.md)。SQLite/PostgreSQL 均继续 TEXT 存储日期/时间，不安排原生 DATE/timestamptz 改造或因此强制切库。

## 1. 不变项与前置盘点

保留账户 ID、密码哈希、管理员标记、单位/字典、参考部件号、原始样品文字、旧记录及历史/审计。未读取业务库前不推断真实数据量；过去清理本地测试数据不代表其他环境无数据。重建不以删除数据库、重新建管理员或重置密码为步骤。

P4 前需明确各环境数据库及备份位置、旧调用方、真实记录/历史范围和维护窗口。输出只读盘点：表/记录数量、迁移版本、空/重复身份、旧工序写法、纸面时间格式、未知批次/设备/人员、旧计数默认零风险。脱敏样例足以评审，不输出密码哈希或会话令牌。

## 2. 数据映射

| 旧数据 | 目标与处理 |
|---|---|
| forms.form_no | 候选 shared_form_no，不能仅因相同就建同一产品批；结合已确认的完整身份型号 |
| sample_raw / 五个拆解项 | 原文逐字保留；完整身份型号人工确认，不能将 VID2 等解析片段自动当完整型号 |
| operation_code | 通过确认映射选择工序字典稳定 ID；别名不自动合并；工序缺失留待核对 |
| 旧 forms 单据 | 明确映射到新单 ID；旧 ID→新单/版本的映射可追溯，重跑不重复创建 |
| 旧版没有批次字段 | **不是业务上明确留空批次**：不能自动推断为整批。人工确认整批或真实批号后才归组/发布 |
| 旧批次/设备线索 | 只有可靠原始证据才填；无证据为未知，不能把明细行或人员/日期当批号生成依据 |
| 纸面人员、单位 | 映射到版本内 paper_*，与 created_by/保存人分开 |
| 表头计数与明细 | 两套原值都保留，拟将表头作为候选 counts、纸面声明及行合计供核对；差异标记，不静默择真 |
| 旧默认零 | 缺值已被存为零时无法自动还原未知，保留原值及“零值语义未核实”迁移标记；不得宣称已知零准确 |
| form_history | 旧保存历史只读保留，必要时映射成 legacy 来源版本；不把每次保存当多次正式检验 |
| ACTIVE/VOID | 不直接等同 v2 PUBLISHED/CANCELLED。VOID 历史保留；ACTIVE 作为候选待核对结果，未经确认不自动发布 |
| 无数量变化 | 明细为空表示未记录，不能造 quantity=0 的损耗结论 |

无法确认身份、归属、整批/分批或数量语义的数据进入迁移暂存/人工核对清单，保留旧域只读可查，不抢占 v2 slot、不入正式统计。待确认后明确建/绑定草稿，再由人员发布，所有动作留来源映射与原因。

同一目标组出现整批与具名分批候选、重复批号、重复旧表时，迁移同样触发新版规则；不得为了导入成功自动追加随机批号。不能把工序合计表与其分批原单同时导入为有效结果。

## 3. 时间字段规范化

目标物理类型仍为 TEXT。日期 `YYYY-MM-DD`；准确时间点 UTC `YYYY-MM-DDTHH:mm:ssZ`；原文独立 *_raw；未知为 NULL。纸面送检/检验分别拆为 *_date、*_at、*_raw，一事件日期/时点二选一。

| 分类 | 处理 |
|---|---|
| 已规范日期 | 验证真实公历日期后写 *_date，原文保留 |
| 已带时区的规范时点 | 解析、转 UTC 秒精度后写 *_at，按业务时区生成 *_day；原文保留 |
| 确定格式的非标准日期 | 使用审核通过的白名单，如四位年在前的 yyyy.M.d；实际日/月有效才写 *_date，记录 parser_rule 与原文 |
| 无时区时刻、小数秒或多义日期（如 03/04/26） | 不自动猜测或截断；标准值 NULL，原文保留，进入待核对 |
| 非法日期（如 2026-02-30） | 标准值 NULL，报告错误并保留原文 |
| 缺失/空串 | 标准值 NULL；原文按证据保留，不填迁移日期或系统当前时间 |

不能通过只给 SQLite 列声明 DATE 或对任意字符串 substr 来声称规范已完成。本轮允许字符串存储，不意味着继续接受任意日期字符串作为正式查询字段。新写入的标准字段非法值返回 422；历史非法值隔离保留，不能导致全批资料丢失。

系统时间盘点覆盖用户锁定/登录、会话创建/见活/过期/撤销、字典、样品确认、业务保存/发布/取消、审计、幂等过期。可信的旧 UTC 秒精度值沿用，不必全库重写；非法会话到期不能默认长期有效。账户和密码不受日期清洗影响，无法信任的会话可失效后重新登录。

业务时区拟定 Asia/Shanghai，须在清洗前确认。只有日期的记录不进行 UTC 换算；时点归日换算，不按 UTC 前十位冒充业务日。例：2026-11-02T16:30:00Z 对应本地 2026-11-03。时区配置变更需记录并评估派生日/报表重算。

## 4. 实施顺序与恢复

1. 只读备份并验证可恢复，记录库版本和数据指纹；确定唯一写入边界与实际调用方。
2. 新增业务表和映射/暂存表，保留旧表及旧迁移；SQLite 与 PostgreSQL 分别 dry-run，不能只验证一种数据库。
3. 导入候选、输出身份/批次冲突与日期分类报告；迁移按源 ID/来源版本唯一映射，重复执行不重复计数。新对象 version/revision_no 不沿用旧 save_count 充当发布次数。
4. 人工处理未知归属、整批语义、零值风险、统计事实来源；确认数据才进入 v2 slot/发布集合。旧统计与新口径差额须能解释。
5. 试点核对同产品批 A-a/b/c、B-c/d，整批工序、后序先录、取消后重建、正式修订、损耗未知及跨午夜日期。
6. 切换期间停止旧业务写入，补最后增量并核对；开启 v2 唯一写入口，旧域只读。基础账户/字典共用不意味着业务域允许双写。
7. 记录切换点、映射与验证报告。若已产生新写入，恢复必须保留/导出切换后数据再决定前滚或重放，不直接覆盖成旧备份。

本轮不执行上述步骤，不启动带 -Reset 的开发脚本，不清理数据，也不编辑已有迁移。

## 5. 迁移验收

| 检查 | 退出条件 |
|---|---|
| 身份 | 同号同完整型号正确归组；不同型号/共享号不误合并；未知原样留待核对 |
| 范围 | 旧无批次不等于新留空，整批/分批冲突及重复号有清单，无法绕过 slot |
| 历史/计数 | 原始资料和历史可查，每单只取一个正式版，不重算出虚构损耗；默认零风险有明确标记 |
| 日期 | 可解析/歧义/非法/缺失数量可核对，原文与转换规则可查，纯日期不补时刻 |
| 安全与账户 | 管理员与普通账户 ID/哈希不变，能登录，过期/无效会话不获得额外有效期 |
| 双库/重跑 | 双库行为一致，重复迁移不新增重复单据，失败能回滚并保留源证据 |
| 切换 | 只有一个业务写入口、备份可恢复、切换后数据有保全方案 |

这是待实施验收标准，当前没有迁移执行结果或生产部署结论。

## 6. 抽检类型迁移补充（2026-11-04）

旧模型无 inspection_kind 标记。已确认来自正常流程的记录映射 NORMAL；明确有抽检证据的映射 SAMPLING；来源无法判断则保留待核对，不按检验量少、批号或缺少损耗自动猜测。新接口缺省 NORMAL 不等于历史数据可无条件默认正常。

工序映射目标键为 `(product_lot_id, operation_id, inspection_kind)`，两类 slot/状态分别维护；相同批号可跨类型共存，绝不通过匹配批号建立正常单与抽检单的关联。迁移核对分别出具正常与抽检记录数、数量及版本集合；抽检不进入正常损耗与良率。历史抽检若有损耗条目保留原证据并人工核对，不静默删除，也不因新版后端未做专属拒绝就认定业务合法。
