## 1. 系统定位（一句话）

**把纸质《镜片表面质量检验记录表》搬到线上的"升级版在线文档"**：录入、留痕、检索、汇总。
**不做**审批流、不做流程管控、不做设备对接。

### 1.1 第一设计原则：最大灵活性（需求 §1.4 F-1~F-8）

| 编号 | 约束 | 对功能的影响 |
|---|---|---|
| F-1 | 不强制任何字段（除表单号） | 任何字段都可以留空保存 |
| F-2 | 不强制顺序 | 可以先填计数后填样品信息 |
| F-3 | 不强制完整性 | 允许"填了一半"，只提示不阻断 |
| F-4 | 不约束工序集合 | 不校验"一份表单应经过哪些工序" |
| F-5 | 不假设使用环节 | 工序现场分次填、次日集中录入、混合使用都要能跑 |
| F-6 | 不收敛未知语义 | 多工序形态、部件号附加成分等不确定信息，**两种可能都保留** |
| F-7 | 默认只警告不阻断 | 校验默认 `warn`；只有调用方显式要求 `strict` 才可能阻断 |
| F-8 | 可扩展优先于精确 | 工序/单位/样品段/部件号/不良列全部走字典，加取值不改代码 |

## 3. 业务数据模型（三个层次）

```
表单 Form（一张纸质表单，form_no 唯一）
├─ 样品信息：sample_raw 原始串（事实来源，永不被改写）
│           + 结构化字段：项目/型号/规格/大小/左右 + 冗余（结构类别/处方属性/参考部件号）
├─ 单位（unit_id 字典 或 unit_text 原文）
└─ 工序记录 FormRecord（一笔 = 该表单的一次工序填写，按 sequence_no 排序）
   ├─ 工序：process_code / process_text（纸质表单未印栏名，系统必须显式呈现）
   ├─ 表单既有栏目：送检人 / 送检时间 / 检验人 / 检验时间 / 操机员 / 交接员
   ├─ 系统留痕：recorded_by（谁录入）/ last_saved_by（谁最后保存）/ save_count（保存次数）
   ├─ 汇总（服务端重算）：total_qty / qualified_qty / defect_qty / pass_rate
   ├─ 完成度：is_complete / missing_fields
   ├─ 计数明细 RecordLine（一行 = 纸质表单的一行，默认 1 行）
   │   检验总数 / 合格品 / 不良品 + 五类不良 × 三表面（15 个子项）
   └─ 历史快照 RecordHistory（每次保存前的完整内容，只增不可改）
```

**为什么是"表单 + 多笔"**：同一张纸质表单要在多个工序中使用，各工序的检验发生在不同时间、可能由不同人填写。拆成"笔"后，每笔只被本次填写的内容更新，历史不会被后续填写覆盖。

### 3.1 计数明细字段（对应纸质表格的列）

| 组 | 子项 |
|---|---|
| 合计 | 检验总数 `total_qty`、合格品 `qualified_qty`、不良品 `defect_qty` |
| 点伤 `spot_*` | 凹面 `_concave`、凸面 `_convex`、双面 `_both` |
| 划伤 `scratch_*` | 同上三面 |
| 脏污 `dirt_*` | 同上三面 |
| 加硬点 `hard_spot_*` | 同上三面 |
| 垃圾点 `debris_*` | 同上三面 |

> 每个子格填的是**该类不良的镜片数量**（不是比例、不是缺陷个数）。
> 已确认：同一片镜片**可能**被计入多个类别 → 子项合计可以大于不良品数。

## 4. 核心功能清单

### 4.1 表单与工序记录管理

| 功能 | 说明 | 状态 |
|---|---|---|
| 新建表单 | 只需表单号；样品信息/单位可稍后补 | ✅ |
| 按表单号取全貌 | 一次拿到表单 + 所有笔 + 每笔明细（"接着填"用） | ✅ |
| 新建一笔工序记录 | 序号自动递增；也可显式指定 | ✅ |
| 更新一笔（增量） | **字段级合并**：只改请求里出现的字段，其余保持原值 | ✅ |
| 整体替换一笔 | `mode=replace`（少用，用于纠正整笔） | ✅ |
| 明细整笔替换 | 提交 `lines` 即整体替换该笔明细（不做行级合并） | ✅ |
| 批量提交多笔 | 一次请求提交"表单 + 多笔 + 每笔明细"（次日集中录入） | ✅ |
| 服务端重算汇总 | 检验总数/合格品/不良品/良率由服务端算，忽略调用方上报值 | ✅ |
| 完成度标记 | 依据缺失项算 `is_complete` 与 `missing_fields` | ✅ |
| 逻辑作废 | 标记 VOID + 原因；数据与历史全部保留，不物理删除 | ✅ |
| 乐观锁 | 传 `expected_save_count`，冲突返回 409 + 服务端当前内容 | ✅ |
| 变更追溯 | 每次保存写入历史快照 + 操作日志；可查两版之间的字段级差异 | ✅ |
| 未完成清单 | 列出"存在未填完整笔"的表单，便于跟进集中录入进度 | ✅ |
| 表单列表与筛选 | 按表单号/样品原始串/状态/待核对/日期/样品维度/单位筛选、分页 | ✅ |
| 批量导入历史表单 | Excel 模板 + 校验报告（需求 M-2，待确认是否需要） | ❓/⏳ |
| 导出/打印 | 复刻纸质表单的导出与打印（需求 Q-5） | ⏳ |
| 表单号自动生成 | `前缀-YYMMDD-流水号`，并发不重号（需求 N-1/N-2） | ⏳（当前由调用方传入） |

### 4.2 两种录入节奏（必须同时支持）

| 场景 | 后端行为 | 状态 |
|---|---|---|
| **A. 工序现场分次填写** | 每次只提交本次能确定的字段；未提交字段保持原值；校验不阻断 | ✅ |
| **B. 次日一次性完整录入** | 可一次提交多笔；调用方可传 `enforce=strict` 做自检；服务端不会因"不完整"拒绝 | ✅ |

> 两种节奏**共用同一套接口与同一套表**，最终数据结构完全一致。

### 4.3 样品信息（双轨存储）

| 功能 | 说明 | 状态 |
|---|---|---|
| 原始串保存 | `sample_raw` 逐字保留，**任何解析或人工修正都不改写它** | ✅ |
| 自动解析 | 位置无关的 token 集合匹配；识别 项目/型号/规格/大小/左右/结构类别/Rx | ✅ |
| 解析缓存 | "原始串 → 结构化结果"缓存，重复录入秒回；记录命中次数 | ✅ |
| 人工确认/修正 | 可改结构化字段；不改写原始串；记录确认人与时间 | ✅ |
| 参考部件号比对 | 与参考清单（序号 05~22）比对，命中即可追溯；**不匹配不算错误** | ✅ |
| 未识别 token | 收集进 `unknown_tokens`，供字典补录；**不报错** | ✅ |
| 待核对清单 | 列出解析不匹配的表单 | ✅ |
| 参考清单维护 | 查询、批量导入（结构化数组或制表符文本） | ✅ |
| 冗余字段 | 结构类别（MONOC/BINOC）、Rx、参考部件号：可空、不校验、不作验收条件 | ✅ |

## 5. 校验规则（V-1 ~ V-10）

> **默认 `enforce=warn`：全部只警告，任何内容都能保存。**
> 只有调用方显式传 `enforce=strict` 时，标 ⛔ 的规则才阻断（返回 422）。

| 规则 | 含义 | 默认 | strict |
|---|---|---|---|
| V-1 | 合格品 + 不良品 = 检验总数（三者都填时） | 警告 | ⛔ 阻断 |
| V-2 | 五类不良 15 个子项合计 = 不良品 | 警告 | **警告**（已确认会重复计数） |
| V-3 | 各类别三子项之和 ≤ 不良品；子项 ≤ 总数 | 警告 | ⛔ 阻断 |
| V-4 | 所有计数为非负整数 | 警告 | ⛔ 阻断 |
| V-5 | 良率 = 合格品 / 检验总数 | 计算（服务端） | 计算 |
| V-6 | 送检时间 ≤ 检验时间 ≤ 当前时间 | 警告 | **警告**（纸面时间常为补记） |
| V-7 | 表单号唯一；同一表单下笔序号唯一 | ⛔ 阻断 | ⛔ 阻断 |
| V-8 | 样品信息与参考清单不匹配 | 警告 + 待核对标记 | **警告** |
| V-9 | 结构化项（项目 M1/M2）缺失 | 警告 | **警告** |
| V-10 | 表单既有栏目缺失（单位/送检人/送检时间/检验人/检验时间/操机员/交接员） | 警告 + 缺失清单 | **警告** |

> 一句话：**"数据自相矛盾"可以在 strict 下被拦住；"还没填完"永远不拦。**
