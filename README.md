## 需求要点速览

1. **两个核心新增点**（相对纸质表单）：
   - 「**工序**」是纸质表单上未印制栏名的独立项目（手写值示例：一次加硬），线上必须显式呈现。
   - 「**样品信息**」双轨存储：`sample_raw` **原始整体输入（事实来源，永不被改写）** + 拆解字段（项目 M1/M2、型号、规格、大小、左右 五个核心 + 结构类别/处方属性 两个**可有可无的冗余**）。
2. **不良计数**：点伤 / 划伤 / 脏污 / 加硬点 / 垃圾点 ×（凹面 / 凸面 / 双面），每格 = **该类不良的镜片数量**。
3. **无审核流程**：保存即录入生效。
4. **同一表单号可多次录入**：不同阶段可能只填一部分，**允许覆盖，系统只保留最新内容**（并保存每次覆盖前的历史快照，可回看与对比差异）。
5. **不在范围内**：送检人 / 送检时间 / 操机员 / 交接员 等纸质栏位，以及表格下方手写率值（属生产部门规章流程）。
6. **用户体系**：账号密码 + 角色（检验员/管理员/只读）+ 权限点 + 覆盖留痕 + 完整审计日志。

## 主要设计取舍

| 主题 | 决定 | 理由 |
|---|---|---|
| 记录唯一键 | `form_no`（一表单号一条当前记录） | 需求：同表单号多次录入只保留最新 |
| 保存语义 | UPSERT 覆盖（整体替换 + 乐观锁 `entrySeq`） | 语义简单，与"一份表单"整体一致 |
| 覆盖留痕 | 覆盖前把旧内容整体写入 `doc_history`（只增不可改） | 质量记录可追溯，用户可在界面回看差异 |
| 样品信息 | `sample_raw` 事实来源；解析与人工修正都不改写它 | 业务方无法确认部件号附加成分含义，故原始输入优先 |
| 校验力度 | 只有 V-1/V-3/V-4/V-6/V-7 阻断；其余仅提示 | 保证"现场永远能存下数据" |
| 不良重复计数 | 已确认存在，V-2 降级为警告并登记待定 | 业务方明确要求延后解决 |
