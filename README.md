# 镜片表面质量检验记录系统（lens-qs）

将纸质《镜片表面质量检验记录表》线上化的系统 —— 定位是**"在线文档的升级版"**：把手工填表变成线上录入，不引入审批与流程管控。
**一切以最大灵活性为先**：不强制字段、不强制顺序、不强制完整、不约束工序集合。

## 需求要点速览

1. **这就是"把手工填表搬到线上"**：纸质表单的既有栏目——单位、送检人、送检时间、检验人、检验时间、操机员、交接员——**一个都不能少**。
2. **唯一与系统无关的手写内容**：表格下方的率值行（如 `A：100%`），不建字段。
3. **工序**是纸质表单上未印制栏名的独立项目（手写值示例：一次加硬），线上必须显式呈现。
4. **样品信息双轨存储**：`sample_raw` 原始整体输入（事实来源，永不被改写）+ 拆解字段（项目 M1/M2、型号、规格、大小、左右 五个核心 + 结构类别/处方属性 两个可有可无的冗余）。参考部件号清单**只是参考**。
5. **真实流程**：一份空白表单在**多个工序现场逐步填写**，全部填完后收齐，**次日由专人统一录入**（现状用 Excel）。系统最终用在哪个环节**尚未确定** → 必须同时支持"分次增量填写"与"一次性完整录入"，**不能因任一假设收紧校验**。
6. **无审核流程**，保存即生效；用户体系保留**管理员 / 普通用户**两级。
7. **不良计数**：点伤 / 划伤 / 脏污 / 加硬点 / 垃圾点 ×（凹面 / 凸面 / 双面），每格 = 该类不良的镜片数量；已确认同一片镜片可能重复计入多个类别（登记待定）。
8. **汇总统计**（按样品信息各子项聚合）已确认需要，**基础分组能力已实现**，去重口径与报表导出待确认。

## 主要设计取舍

| 主题 | 决定 | 理由 |
|---|---|---|
| 强制程度 | 除 `form_no` 与 `(form_id, sequence_no)` 唯一外**不做任何强制** | 生产流程繁杂且无法确认，系统不得用流程约束绑住现场 |
| 数据模型 | **三层**：`Form`（一张纸质表单）→ `FormRecord`（一笔工序填写）→ `RecordLine`（一行计数） | 多工序分次填写需要每笔独立的人员/时间/历史，单条记录会被后续填写覆盖 |
| 保存语义 | **字段级合并**（未提交字段保持原值）+ `enforce: warn \| strict` 控制校验强度 | 兼容"不同工序/不同人只填自己那部分"，同时让集中录入走同一套接口 |
| 校验力度 | **默认只警告**；只有调用方要求 `strict` 时才阻断，且 V-2/V-6/V-8/V-9/V-10 **永不阻断** | "还没填完"绝不能挡住现场保存，否则分次录入无法成立 |
| 明细行 | 提交即**整笔替换**（不做行级合并） | 避免"半行数据"歧义，行级粒度不值得做合并 |
| 留痕 | 每次保存前把该笔快照写入 `record_history`（只增不可改）+ `audit_logs` | 质量记录可追溯；粒度到"笔"比"整表"更贴合现场 |
| 表单人与录入人 | 表单人员字段按**纸面文字**存；另用**系统用户**记录创建者/更新者/本次修改者 | 次日集中录入时二者通常不同；不把系统账号绑到纸面人名上 |
| 工序归属 | **笔与行都保留工序字段** | 多工序落库形态无法确认（"每工序一行" vs "分次补齐同一组栏目"），两种现实都要能表达 |
| 权限 | 只有两级，判定集中一处 | 生产部门人员安排未定；将来收紧不改业务代码 |
| 不良重复计数 | 已确认存在，V-2 恒为警告，登记待定 | 业务方明确要求延后解决 |
